# E2 — Banco gerenciado e Kubernetes automatizados

[Índice central](../../../PLANO_FASE_3.md) · [Evidências e pendências](../ACOMPANHAMENTO.md)

Consultar conforme a tarefa: [infraestrutura](../decisoes/INFRAESTRUTURA.md), [ambientes](../decisoes/REPOSITORIOS_E_AMBIENTES.md) e [persistência](../decisoes/NEGOCIO_E_PERSISTENCIA.md). Atualizar os checkboxes somente neste arquivo.

- [ ] E2.1 Adaptar o Terraform existente para hom/prd independentes e coexistentes na mesma conta/us-east-1, com VPC e subnets em duas AZs por ambiente; parametrizar nomes/estados/referências e um nó t3.medium On-Demand por cluster (mínimo/desejado/máximo 1), conforme D05.2.
- [ ] E2.2 Criar Terraform do Aurora PostgreSQL Serverless v2 Standard: um writer db.serverless por ambiente, sem reader, faixa inicial 0–2 ACUs e auto-pause de 300 segundos; fixar versão compatível, conectividade, permissões e configuração para API/função. Aplicar D01.2/D05.2 mantendo probes atuais.
- [ ] E2.3 Implementar backend S3 com versionamento e locking nativo use_lockfile, estados separados por unidade/ambiente e bootstrap independente do descarte normal (D09.1); validar concorrência sobre o mesmo estado.
- [ ] E2.4 Implementar pipelines de provisionamento e atualização para homologação e produção, com validação e aplicação controlada dos planos.
- [ ] E2.5 Versionar criação do esquema final e seeds para banco vazio; executar Job Kubernetes pela pipeline do banco após provisionar Aurora e antes dos consumidores/testes, sem migração de dados (D08.1/D05.1). Manter banco local do Compose para desenvolvimento.
- [ ] E2.6 Atualizar conexão e secrets da API para o banco gerenciado e retirar da implantação em nuvem os recursos PostgreSQL internos que deixarem de ser necessários.
- [ ] E2.7 Validar probes, recursos, réplicas, HPA e comunicação com o banco na nova arquitetura.
- [ ] E2.8 Documentar inicialização, falhas e descarte/recriação independente por ambiente, sem snapshot final/backups retidos no descarte normal do banco educacional (D05.2); preservar base compartilhada e outro ambiente. Alterações de esquema no script final de criação, sem migração de dados (D08.1).
- [ ] E2.9 Implementar D01.4/D09.2: subnets privadas, rotas/security groups, NAT Gateway zonal único com Elastic IP e gateway endpoint S3; manter Aurora sem rota de internet. Habilitar endpoint administrativo EKS público/privado e acesso das roles OIDC dos runners GitHub ao Kubernetes; preservar HPA e probes.
- [ ] E2.9a Incluir exclusão do NAT e liberação do Elastic IP no descarte, após limpeza dos consumidores/dependências; preservar backend/identidade conforme D09.1.
- [ ] E2.10 Configurar controlador e Service LoadBalancer para NLB interno, definir destinos e disponibilizar os outputs necessários à integração VPC Link da REST API; evitar propriedade duplicada de recursos entre Terraform e controlador.
- [ ] E2.11 Provisionar ECR privado e política de retenção; definir permissões de push/pull e atualizar pipeline/manifests da aplicação para publicar e consumir a imagem identificada por commit/digest, substituindo Docker Hub.
- [ ] E2.12 Preparar D01.5: credencial de leitura limitada para Lambda, segredos no Secrets Manager, IAM e conectividade privada com Aurora/Secrets Manager; definir consumo da mesma chave JWT pela API sem expor valores em repositórios, logs ou outputs.

- [ ] E2.13 Provisionar bucket privado de artefatos separado do backend, com versionamento, publicação sem sobrescrita, checksums, referências fixas e retenção das versões implantadas/rollback; disponibilizar acesso OIDC por escopo (D09.3).
- [ ] E2.14 Implementar hierarquia SSM /mecanica/<hom|prd>/<componente>/v1/<campo>, produtores únicos, revisão pronta e invalidação no descarte; manifesto de implantação por ambiente e coordenação de operações entre repositórios (D09.3).

**Critério de conclusão:** cluster e banco gerenciado provisionados por pipelines, esquema/seeds criados a partir de banco vazio, API acessando o banco e health checks aprovados. Evidências por ambiente registradas; inicialização reproduzível conforme D08.1.
