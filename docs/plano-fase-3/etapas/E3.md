# E3 — Autenticação serverless e API Gateway

[Índice central](../../../PLANO_FASE_3.md) · [Evidências e pendências](../ACOMPANHAMENTO.md)

Consultar conforme a tarefa: [infraestrutura/Lambda](../decisoes/INFRAESTRUTURA.md), [contratos entre componentes](../decisoes/REPOSITORIOS_E_AMBIENTES.md) e [especificação de acesso](../../arquitetura/ACESSO_E_AUTENTICACAO.md). Atualizar os checkboxes somente neste arquivo.

- [ ] E3.1 Implementar Lambda C#/.NET 10 para `POST /customers/validate`, com validação/normalização de CPF e consulta direta parametrizada ao Aurora via Npgsql/Dapper; 200 com token ou 401/400 conforme D02.2/D01.5.
- [ ] E3.2 Emitir JWT conforme D02 e rejeitar solicitações incompatíveis com as regras definidas.
- [ ] E3.3 Implementar AWS API Gateway REST API Regional via definição OpenAPI 3.0 versionada e Terraform/pipeline; configurar extensões AWS, destinos por ambiente, rota de validação na função e acesso à aplicação no cluster. Validar importação e atualização sem divergência de contratos (D01.3).
- [ ] E3.4 Configurar validação do token e propagação de identidade conforme a arquitetura escolhida.
- [ ] E3.5 Testar CPF inválido, cliente inexistente, status não elegível, autenticação válida e tokens inválidos/expirados.
- [ ] E3.6 Implementar CI/CD e deploy automático da função em ZIP/runtime gerenciado dotnet10 para hom/prd (D01.5/D05.2), com 512 MB, timeout 15 s e concorrência reservada 5, sem provisionada; conferir quota da conta e comportamento funcional antes da demonstração.
- [ ] E3.7 Atualizar Swagger/Postman e o diagrama de sequência com o fluxo real.
- [ ] E3.8 Implementar VPC Link e integração REST API com NLB interno conforme D01.4; validar caminhos, cabeçalhos e acesso privado ao backend.
- [ ] E3.9 Aplicar D01.5: função na VPC, TLS, Secrets Manager, conexões assíncronas sem pooling e sem RDS Proxy; configurar memória/timeout/concorrência com base nos testes, preservando configuração da API.
- [ ] E3.10 Validar compatibilidade das regras de CPF/JWT, fechamento de conexões no sucesso/erro e resposta 5xx em falhas técnicas; habilitar logs JSON e tracing correlacionado com Gateway e consulta, conforme D01.5 e integração de observabilidade E5.

- [ ] E3.11 Publicar contratos OpenAPI de API/função por revisão e compor/aplicar Gateway por workflow reutilizável da infraestrutura fixado por commit; validar compatibilidade, contexto OIDC/checkout, concorrência e registrar versões exatas no manifesto (D09.3).
- [ ] E3.12 Consumir NuGet CPF/JWT de versão fixa na Lambda, baixando nupkg do S3 para feed local antes do restore; documentar fluxo local sem checkout da API (D09.3).

**Critério de conclusão:** um cliente elegível obtém JWT via Gateway e acessa uma rota protegida; casos negativos são rejeitados; o deploy da função é reproduzível pela pipeline.
